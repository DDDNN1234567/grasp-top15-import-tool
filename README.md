# 管家婆辉煌 TOP15 双向直导工具 v3.1

千业管理通（商贸通 Bas 库）↔ 管家婆辉煌 TOP15（标准账套，SQL Server）**双向 100% 直导**工具，覆盖基本资料、**16 方案完整预设价格（含客户自定义门店价）**、客户价格追踪、**当前结存库存**、条码、辅助单位（真实换算率），以及**期初委托/受托、借进/借出**业务数据。

v3.1 在 v3.0 基础上增强健壮性与自动化：**自动附加向导、增量 upsert、一键回滚最近备份、数据库下拉选择、版本感知驱动、字段动态补全**。

## v3.1 相对 v3.0 的改进

1. **.mdf/.ldf 自动附加向导**：界面选 .mdf（.ldf 可选）→ 自动 ATTACH → 校验千业 Bas 结构 → 自动填入源库，全程无需手工操作；版本不兼容、文件锁、非 Bas 结构均给中文提示。
2. **增量 upsert**：基于 BaseNo/usercode 集合差异，源独有新增、共有更新名称/联系/备注、目标独有保留不删，不再每次全量重建（全量模式仍保留）。
3. **数据库下拉手工选择**：连接后自动枚举在线数据库填充下拉，也可手工输入（对齐早期本机版本）。
4. **事务回滚加固 + 一键回滚**：回滚前预检备份完整性（任一缺失即中止，绝不半回滚）；新增"一键回滚最近备份"，无需手填前缀。
5. **版本感知驱动矩阵**：连接前探测 SQL Server 版本，2005 用 SNAC、2008+ 用 ODBC17/18，按驱动链逐个尝试，老环境容错更强。
6. **字段动态补全**：当前应收应付、预收预付、预警、停用、最近进价等主表冗余字段按源值动态补全；备注类字段以"标签:值"幂等追加。
7. **拼音健壮化**：拼音补齐改为存在性检查 + 异常兜底，辅助功能不再阻断主流程（修复 21:28 日志 4121 导致整体误报失败）。
8. **Excel 接口加固**：xlrd 模块级容错（缺失不影响 .xlsx），.xlsx 走 openpyxl、.xls 走 xlrd。

## v3.0 相对 v2.0 的改进

2. **帮助弹窗**：每个功能按钮旁加蓝色"?"，点击弹出该功能的用途、填写口径与注意事项（共 15 组帮助）。

## 核心能力

1. **16 方案完整价格**：动态解析管家婆价格类型与千业 IndexID，系统价（零售/最近进/最近售/最低）走主表锚点，自定义价（0104-0118）先名称强匹配、未中再分配空槽，客户门店价、现金价、预设价全部不漏。
2. **真实换算率**：千业 `Percent*` = 辅助单位换算率（非毛利率），双向 URate 一致（个→箱 48/24/108 等）；无辅助单位槽位正确写 0、不写误率。
3. **当前结存口径**：库存取 `StorageGoodsInfo` 当前结存，不读历史期初表；负库存符号自动对齐（数量与金额同号）。
4. **业务数据对应**：期初委托/受托（11 列）、借进/借出（7 列）按类型映射，虚拟借出/借入仓编号两软件一致。
5. **通用设计**：不写死具体账套，任意含自定义价格列的千业 Bas 账套均可处理。

## 关于 .mdf / .ldf 文件（v3.1 已支持自动附加）

.mdf/.ldf 是 SQL Server 的数据库主/日志文件，不是通用可交换格式，普通进程无法直接解析，**必须先由 SQL Server 附加（ATTACH）为数据库**再经 ODBC 处理。v3.1 已把这一步收进界面：

- 在"千业→管家婆（正向）"页的**自动附加向导**：选择 .mdf（.ldf 可不选，SQL Server 自动重建日志）→ 填新库名（留空取文件名）→ 点"自动附加并设为源库"，工具自动 ATTACH、校验 Bas 结构并填入源连接，随后可直接执行正向直导，**全程无需手工附加**。

仍需注意的边界：

1. **版本约束**：高版本文件不能附加到低版本实例（如 2016 的库不能挂到 2008），工具会识别 5170/5172 并中文提示。
2. **结构约束**：只识别千业商贸通 Bas 结构（Bas* 四表），非该结构、加密或损坏文件无法按 Bas 流程导入。
3. **文件锁**：文件被千业软件占用或无访问权限时（5120/5123），需先关闭千业软件、解除占用后重试。
4. RECOVERY_PENDING 状态需先修复。
